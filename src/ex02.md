## Время

### 4. Сколькими способами в журнале записано время и сколько строк в каждом?

**Ответ:** в журнале **два формата** записи времени:
- `YYYY-MM-DD HH:MM:SS` — **858 строк**;
- `DD.MM.YYYY HH:MM:SS` — **143 строки**.

**Чем получено:**
```sql
SELECT CASE
         WHEN substr(ts, 5, 1) = '-' THEN 'YYYY-MM-DD HH:MM:SS'
         WHEN substr(ts, 3, 1) = '.' THEN 'DD.MM.YYYY HH:MM:SS'
         ELSE 'неизвестный формат'
       END AS timestamp_format,
       COUNT(*) AS rows
FROM access
GROUP BY timestamp_format
ORDER BY timestamp_format;
```

### 5. В каком часовом поясе записано время в журнале доступа? В каком — в файле тикетов? Откуда это известно?

**Ответ:** согласно таблице исходных данных в `README.md`, журнал доступа панели `data/access.csv` ведётся в **UTC**, а заявки поддержки в `data/tickets.csv` — в **московском времени (UTC+3)**. Это также поясняется в `materials/logs_rus.md`: серверные журналы обычно используют UTC, а московское время на три часа опережает UTC. Для конкретной проверки можно сопоставить заявку `T-4471` (23:14 11 сентября по Москве) с записью `mfa_reset` в журнале (20:31:18 UTC, то есть 23:31:18 по Москве): события идут в согласованном порядке с разницей около 17 минут.

**Чем получено:**
```sh
# Таблица файлов и их часовых поясов в README
sed -n '106,114p' README.md

# Сопоставить заявку T-4471 со сбросом MFA в access.csv
grep '^T-4471,' data/tickets.csv
grep ',mfa_reset,' data/access.csv
```

### 6. Сколько событий попадёт в выборку за 12 сентября по журналу как есть и сколько — после перевода в московское время? Почему числа разные?

**Ответ:** по дате в журнале без сдвига на часовой пояс набирается **5 событий** за 12 сентября. После перевода UTC в московское время — **9 событий**. Разница в четыре события возникает потому, что записи с 21:00 до 23:59 UTC 11 сентября уже относятся к 12 сентября в Москве (UTC+3). Перед фильтрацией смешанные текстовые форматы времени нормализуются функцией `portm`, зарегистрированной в `src/ex01.py`.

**Чем получено:**
```sql
-- Дата в журнале, без перевода из UTC в MSK
SELECT COUNT(*)
FROM access
WHERE substr(portm(ts), 1, 10) = '2026-09-12';

-- Та же выборка после сдвига UTC+3 (московское время)
SELECT COUNT(*)
FROM access
WHERE date(datetime(portm(ts), '+3 hours')) = '2026-09-12';
```

### 8. Из каких городов заходили в панель? Какие адреса принадлежат не офису и не домашнему провайдеру?

**Ответ:** среди событий `action = 'login'` в журнале встречаются пять городов: **Екатеринбург, Москва, Новосибирск, Санкт-Петербург и Сочи**.

По справочнику `geoip.csv` адреса, чьи организации не отмечены ни как офис, ни как домашний провайдер:
- `10.9.2.10` — серверная «Привал», Москва (внутренний серверный адрес);
- `176.59.208.33` — мобильный оператор, Сочи;
- `185.220.101.45` — хостинг-провайдер VPS, указан город Москва;
- `45.132.19.88` — хостинг-провайдер VPS, Франкфурт.

**Чем получено:**
```sql
-- Города из записей входа в панель; город берётся из справочника по JOIN
SELECT DISTINCT g.city
FROM access AS a
JOIN geoip AS g ON g.ip = a.ip
WHERE a.action = 'login'
ORDER BY g.city;

-- Адреса, не классифицированные как офисные или домашние провайдеры
SELECT ip, city, org
FROM geoip
WHERE org NOT LIKE 'офис%'
  AND org NOT LIKE 'домашний провайдер%'
ORDER BY ip;
```

### 9. Какие адреса впервые появляются в журнале начиная с 9 сентября? Сколько раз встречается каждый?

**Ответ:** три IP-адреса впервые встречаются в журнале начиная с 9 сентября (дата и время — по исходному UTC-журналу):

| IP-адрес | Первое событие (UTC) | Всего строк с этим IP в журнале |
|---|---|---:|
| `45.132.19.88` | 2026-09-09 01:17:09 | 2 |
| `176.59.208.33` | 2026-09-11 23:55:04 | 3 |
| `185.220.101.45` | 2026-09-12 00:01:14 | 5 |

**Чем получено:**
```sql
WITH normalized AS (
    SELECT ip, portm(ts) AS ts
    FROM access
),
first_seen AS (
    SELECT ip, MIN(ts) AS first_seen_utc, COUNT(*) AS total_events
    FROM normalized
    GROUP BY ip
)
SELECT ip, first_seen_utc, total_events
FROM first_seen
WHERE substr(first_seen_utc, 1, 10) >= '2026-09-09'
ORDER BY first_seen_utc;
```
